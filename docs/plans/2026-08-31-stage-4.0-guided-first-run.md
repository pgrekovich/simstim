# Stage 4.0: guided first run

## Goal

Make a fresh install ready for its first recording without hiding the ordinary
Settings path or requiring sound merely to grant macOS permissions.

## Product contract

1. The first launch explains that capture is local and starts only after an
   explicit click.
2. The welcome page shows the notes folder and lets the user choose another.
   A fresh config defaults to `~/Documents/simstim` on macOS.
3. Entering the permissions page automatically requests microphone and system
   audio access through the production APIs. The page reports the two
   permissions independently and never requires speech, music, or a measured
   signal. `Check again` is a secondary action for returning from System
   Settings.
4. Entering the transcription step automatically downloads the required live
   model. The UI uses a product name rather than an engine name, and retains a
   manual action only for retry after failure. The four official ONNX files are
   downloaded directly with one continuous progress bar, avoiding the old
   archive extraction pause.
5. Summary setup is an optional final step. It exposes the same local, Claude
   Code and Codex providers, cloud model choice, automatic summaries, generated
   titles and calendar context as Settings. The local summary model can be
   downloaded in place through the shared model operation.
6. Settings remains available from every step. It is not replaced by a second
   configuration system.
7. Completion is stored as `onboarding_complete` in the normal TOML config.
   Setting it by hand is supported like every other setting.
8. Recording entry points are disabled in the UI and rejected by the backend
   until setup is complete. Call detection also stays quiet until completion.

## Implementation

- Add a small backend permission-check state with a concurrency guard.
- Add `check_audio_permissions` and `complete_onboarding` IPC commands.
- Add one full-window React onboarding surface with Welcome, Permissions,
  Recording model and Summaries steps.
- Keep `SettingsDialog` mounted above onboarding so downloads and output-folder
  changes continue through the existing path.
- Extend App shortcut, banner and menu-bar gates with onboarding state.

## Verification

- Rust tests cover completion gates plus config round trips.
- React tests cover automatic permission requests, independent failures, retry,
  folder selection, model download progress, Settings access and completion.
- Run all four project gates before owner e2e.
