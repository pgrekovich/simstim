# simstim Stage 0.8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner pick which whisper model re-transcribes his calls (bigger models may read Russian better) and delete downloaded models to reclaim disk.

**Architecture:** The model registry grows a role concept (`live` = the recording engine, `retranscribe` = the whisper family) and several whisper entries. Config gains the selected re-transcribe model. A `delete_model` command removes a model's files. The settings Models list becomes a real manager: grouped by role, radio selection within the re-transcribe group, per-row delete with confirmation, and total disk usage.

**Tech Stack:** existing workspace, no new dependencies.

## Global Constraints

- Registry entries gain `role: ModelRole` (`Live` | `Retranscribe`). Parakeet is `Live` and stays the only live entry (still not user-switchable: the existing `selectable` behavior for live models is unchanged). Whisper entries are `Retranscribe`.
- Whisper entries to offer (all single-file GGUF from the whisper.cpp Hugging Face repo `ggerganov/whisper.cpp`, `resolve/main/<file>`). **Confirm every URL and byte size with a HEAD request before hardcoding; if one 404s, drop it and say so in the report:**
  - `ggml-large-v3-turbo-q5_0.bin` (smallest, fastest)
  - `ggml-large-v3-turbo-q8_0.bin` (current default, keep the existing id `whisper-large-v3-turbo-q8` so existing configs and downloaded files keep working)
  - `ggml-large-v3-q5_0.bin` (non-turbo, quantized)
  - `ggml-large-v3.bin` (non-turbo, full)
  Name them in the UI so the tradeoff is legible, e.g. "Whisper large-v3-turbo (q8) - faster" and "Whisper large-v3 - slower, usually better on non-English". Include the measured speed reference we already have (turbo q8 ran at about 12x realtime on this machine) in the helper text; do NOT invent numbers for the models we have not measured, describe them relatively.
- Config gains `retranscribe_model: String`, serde default `whisper-large-v3-turbo-q8` (old configs load unchanged). `set_retranscribe_model(id)` validates that the id exists AND has role `Retranscribe`.
- `retranscribe_session` uses `config.retranscribe_model` instead of a hardcoded id. Its existing "model not downloaded" rejection must name the selected model.
- New `delete_model(id) -> Result<(), String>` command: removes the model's files from the models dir (single-file: the file; archive layout: the extracted dir). Rejections with user-facing messages: a download for that id is in flight; a re-transcribe job is running; the model is a `Live` model that the app needs to record (deleting parakeet must be refused with a clear message, since recording would break). Deleting the currently selected re-transcribe model IS allowed: the existing "not downloaded" rejection already covers the consequence, and the UI must show the row as not downloaded afterwards.
- `list_models` gains `role` and `size_on_disk_bytes: u64 | null` (actual bytes on disk when downloaded, so the UI can show real usage rather than the advertised size).
- UI (Settings > Models): two labelled groups, Recording and Re-transcribe. Re-transcribe rows carry a radio-style selection (only among downloaded models; selecting a not-downloaded model is not offered). Every downloaded row gets a delete control (trash icon) that asks for confirmation before deleting (a small inline confirm is fine, no new dialog component needed), then refreshes. Show total disk used by downloaded models in the group header or under the list. Must look right in light and dark.
- Everything else stays: single-writer rule, no telemetry, no network beyond model downloads, conventional commits without co-author lines, no em dashes in authored copy.
- Every task ends with `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `pnpm test`, `pnpm build` green.

### Task 1: Registry roles, model selection, delete command

**Files:** `apps/desktop/src-tauri/src/models.rs`, `config.rs`, `lib.rs`, `retranscribe.rs`, `apps/desktop/src/lib/ipc.ts` (types and wrappers only, no UI).

**Interfaces produced:**
- `ModelRole` enum on `ModelSpec`; the four whisper entries above plus the unchanged parakeet entry.
- `ModelInfo` gains `role: String` and `size_on_disk_bytes: Option<u64>`.
- `set_retranscribe_model(id: String) -> Result<(), String>`, `delete_model(id: String) -> Result<(), String>`.
- `Config::retranscribe_model` with the serde default above.
- `retranscribe_session` reads the selected model; its missing-model message names it.

Tests: registry contains the expected roles/ids; `set_retranscribe_model` rejects an unknown id and a `Live` id; `delete_model` removes a single-file model and an archive-layout model (tempdir fixtures), refuses the live model, refuses while a download of that id is in flight and while a re-transcribe job runs; `size_on_disk_bytes` reports real bytes for a fixture and null when absent; old config without `retranscribe_model` loads with the default.

Commit `feat(models): roles, re-transcribe model selection and deletion`.

### Task 2: Model manager UI

Tests: selecting a downloaded re-transcribe model calls `setRetranscribeModel` and reflects the new selection; delete asks for confirmation and only calls `deleteModel` after confirming; the live model row shows no delete control; a not-downloaded model offers Download but no selection.

Commit `feat(ui): model manager with selection and deletion`.

## Self-review notes

- Keeping the existing whisper id stable is load-bearing: the owner already downloaded that 874 MB file and must not be asked to download it again.
- `delete_model` touches the same models dir the downloader writes: the in-flight-download rejection is what keeps them from racing; verify the guard covers both directions.
- The live/re-transcribe split is the same data-driven pattern stage 0.7 introduced with `selectable`; prefer generalizing that field into `role` over adding a second parallel flag, and keep the backend validation that a `Live` model cannot be set as the live engine by hand.
