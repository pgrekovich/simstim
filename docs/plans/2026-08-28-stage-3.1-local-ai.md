# Stage 3.1: built-in local summaries

Date: 2026-08-28. Status: implemented on `codex/stage-3.1-local-ai`, awaiting
owner M1 quality and memory e2e.

## Outcome

The existing Enhance action can run entirely on-device through a downloaded
Qwen3.5 9B model on Macs with at least 16 GB. The tested 4B checkpoint is not
offered because its smaller download and faster output did not justify lower
factual accuracy or a second local mode. Claude Code and Codex remain available
as explicit cloud alternatives. This stage establishes the reusable local
inference backend; knowledge chat is not added yet.

## Global constraints

- No recording, note or transcript leaves the machine through the local
  provider.
- Do not require Ollama, Homebrew, Python, an account, or a background server.
- The model is downloaded only after an explicit click with size visible.
- The user's Notes and Transcript are immutable. Generated text replaces only
  `## Summary` through the existing atomic rewrite.
- Never run the summary model while the target call is recording or
  finalizing. At most one Enhance runs app-wide.
- Do not persist a chat database or model cache outside the existing models
  directory.
- Preserve existing Claude Code and Codex configurations during migration.
- Make Local the default for new installs and configs that predate Enhance.
- No merge without the owner's native e2e.

## Implementation slices

1. Add the Qwen model to the registry with a Summary role, download progress,
   deletion and accurate disk usage. Add the local provider to Settings.
2. Bundle a pinned llama.cpp Rust worker with Metal support and implement a
   bounded text-generation adapter with thinking disabled. Keep it in a
   short-lived helper process because Whisper embeds a conflicting GGML build
   in the main application process.
3. Route the existing Enhance pipeline through either the local adapter or
   the existing CLI provider without duplicating the single-writer and atomic
   save rules.
4. Add output validation, one retry for an empty response, cancellation-safe
   slot cleanup and exact `local/qwen3.5-9b-q4-k-m` summary labeling.
5. Test registry behavior, config migration, prompt/template construction,
   provider selection, failed generation and real file writes. Run the four
   project gates, then perform a manual M1 quality and memory check on a real
   short and long meeting.
6. Tune on the owner's real noisy Russian call: compact prompt-only transcript
   input, ground status versus plans and conditional actions, enforce the
   spoken language, and compare 4B against 9B before selecting the single
   supported checkpoint.

## Deliberately deferred

- Ask this call and Ask all notes.
- Persistent conversational history.
- Automatic model download during onboarding.
- More local checkpoints beyond the selected 9B profile.

## Acceptance

- A user can download/delete Qwen from Settings and see live progress.
- Selecting Local keeps all content on-device and produces a labeled Summary.
- Enhance stays responsive and cannot run against an active/finalizing note.
- Missing model, load failure, empty generation and timeout have readable
  errors and never modify the file.
- Existing cloud Enhance providers still work unchanged.
- The downloaded model is not held in memory after generation completes.
- Long calls are summarized through local chunk extraction plus a final local
  synthesis pass instead of being silently truncated.
