# Stage 4.1: settings redesign

## Goal

Make Settings read the way the owner's approved mockup does: five task-shaped
categories, meta-named models with quiet engine names, one-line row copy with
group-level explanations, and a Storage page that also weighs the user's own
notes and audio.

## Global constraints

- No behavior changes to any setting's semantics. This stage moves and
  re-words controls; every toggle keeps writing the same config field with
  the same meaning.
- Sub-row nesting (indent + dim when the parent is off) is allowed only where
  the dependency is real: auto-stop under call detection, audio format under
  keep-audio. Settings that also affect manual runs stay flat.
- The registry's `name`/`technical_name` split is the single source of model
  naming; the README's model list quotes registry names exactly.
- Retired model rows keep their existing names and delete-only behavior.
- All four gates green before owner e2e; React tests assert real IPC calls,
  not just rendering.

## Product contract (from the approved mockup)

1. Left rail: General, Recording, Transcription, Summaries, Storage.
2. General: Appearance (System/Light/Dark), Show in Dock, Notes folder.
3. Recording: "Suggest recording when a call starts" with "Stop when the call
   ends" nested; "Keep audio files" with "Format" (AAC/FLAC) nested and a
   footnote giving the per-hour sizes.
4. Transcription: Live group (meta-name "Live transcription", Parakeet small,
   "good, not perfect" footnote), then "Accurate pass · after the call" with
   the why-and-cost paragraph, the whisper rows ("Balanced" /
   "Best quality"), "Run automatically after each call", and the flat
   "Delete audio after re-transcribing" row.
5. Summaries: intro paragraph ranking cloud above on-device honestly;
   provider rows ("On this Mac" + Qwen small with download/delete, Claude
   Code with model menu, Codex); then "Summarize after each call",
   "Allow renaming notes", "Use calendar for context" as flat rows.
6. Storage: "Your calls" (notes count + bytes, audio hours + bytes, the
   "yours to move, sync or delete" footnote) and "Models" (existing rows
   with sizes and delete controls).
7. Settings vocabulary says "Summarize"; the session view's Enhance button is
   out of scope.

## Implementation

Ordered so the pieces the owner is most likely to re-decide come first.

1. Registry naming (`models.rs`): whisper rows become "Balanced" /
   "Best quality" with `technical_name` carrying the engine names; taglines
   trimmed to match the mock. README model list updated to match. Qwen and
   Parakeet rows already carry the right split.
2. New `storage_stats` IPC command (`sessions.rs` + `lib.rs` registration +
   `ipc.ts`): one pass over the notes folder summing parsed-session `.md`
   count and bytes, resolved audio files' bytes, and audio hours from those
   sessions' `duration_secs`. No caching; the folder is local.
3. `SettingsDialog.tsx` restructure: five nav sections, rows regrouped per
   the contract, sub-row dim wiring for the two real dependencies, copy
   rewritten (one-line descriptions, group intros, "Summarize").
4. Storage section rendering `storage_stats` plus the existing model rows.
5. Tests: Rust unit tests for `storage_stats` on a fixture folder (real
   bytes, files with and without audio); React tests for nav sections,
   dependent-row dimming, storage rendering, and that every relocated
   control still fires its original IPC call.
