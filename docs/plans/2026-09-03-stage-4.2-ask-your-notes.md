# Stage 4.2: ask your notes

## Goal

Ship both chat surfaces from the design: **Ask your notes** (artboard 8b - a
full-pane conversation over the whole notes folder, pinned sidebar row, `⌘L`)
and **Ask this call** (artboard 8c - a 300 px drawer over the open note,
`⌘J`, working live mid-call), with cited, source-chipped answers running
through the user's own AI CLI.

## Global constraints

- **Files are the database.** No index, no cache, no chat persistence. The
  CLI reads the folder directly on every ask; conversations live in backend
  memory and die with the app.
- **CLI providers only** (`claude` / `codex`), never the embedded local
  model: no GPU contention with live ASR, so asking mid-call is always safe.
- **Read-only data access.** claude runs in a fresh empty temp dir with
  `--add-dir <notes folder>` and only `Read,Grep,Glob` allowed; codex runs
  `exec -s read-only` in the notes folder. Nothing chat-related may ever
  write a note file.
- **Mid-call reads come from the on-disk file** (lines are flushed as they
  finalize); reads never touch the single-writer rule.
- **Stateless per ask**: one fresh subprocess per question; the prompt
  replays a bounded conversation history. No CLI `--resume` in this stage.
- **The reply contract is line-oriented** (`SOURCE:` / `FOLLOWUP:` trailing
  lines, peeled off like enhance's `TITLE:`), never JSON-wrapped markdown.
- One in-flight ask per scope; scopes independent of each other and of the
  enhance slot; a running ask is cancellable (subprocess killed) and dies at
  a timeout.
- Answers must be in the question's language.
- All four gates green before owner e2e; tests assert prompt shape, reply
  parsing, validation and real IPC calls.

## Implementation

1. **Backend `chat.rs`**:
   - `ChatState`: `Mutex<HashMap<String, Conversation>>` keyed by scope
     (`"all"` or a note path). `Conversation` holds `Vec<ChatMessage>`
     (`role`, `text`, `sources`, `followups`, `asked_at` clock time) and a
     kill handle for the running child.
   - Prompt builders (pure, unit-tested): all-notes prompt (folder layout
     description, tool instructions, citation + followup + language rules,
     history replay, question) and this-call prompt (title + user notes +
     raw timestamped transcript inline, other-notes access note, same
     rules). History replay bounded (last 6 exchanges, answers truncated).
   - Reply parser (pure, unit-tested): peels trailing `SOURCE:` /
     `FOLLOWUP:` lines; `SOURCE: <file> @ <hh:mm:ss>`, `SOURCE: <file>`,
     `SOURCE: <hh:mm:ss>` all valid; malformed lines stay in the answer
     text harmlessly.
   - Subprocess runner: shares `resolve_binary` and the poll-with-deadline
     kill discipline with enhance (helpers become `pub(crate)`), 180 s
     timeout, child handle stored for cancel.
   - Commands: `chat_ask(scope, question)` (async, spawn_blocking, returns
     the assistant `ChatMessage`), `chat_history(scope)`, `chat_clear(scope)`,
     `chat_cancel(scope)`. `chat-progress` events (`running`/`done`/`error`)
     so a remounted UI recovers in-flight state.
   - Validation: onboarding complete, provider CLI available, no ask already
     running for the scope. Empty transcript mid-call is allowed (the model
     answers "nothing yet").
2. **Config**: `chat_provider` (`"claude"` default, `"codex"`) and
   `chat_model` override + setters + Settings Summaries page gains an
   "Ask your notes" group (provider picker reusing the availability probe,
   model override field).
3. **`ipc.ts`**: `ChatMessage`, `ChatSource`, `chatAsk/chatHistory/
   chatClear/chatCancel`, `ChatProgress` event type, config fields.
4. **Frontend components**:
   - `ChatConversation` (shared): YOU-ASKED question blocks in serif ink,
     bordered machine-material answer boxes labeled `FROM N NOTES · MACHINE`
     + provider/model, source chips, followup chips, input bar, thinking
     state, error state, cancel.
   - `AskNotesView`: full-pane surface (header + "N notes · X h" badge from
     `storage_stats`, footer hint "answers cite the note and the second").
   - `AskCallDrawer`: 300 px right drawer, header "Ask this call", close
     button, `⌘J` placeholder hint.
   - Sidebar pinned "Ask your notes" row (`⌘L`); GlobalSearch bottom row
     "Ask across all notes: <query>" (`⌘↵`).
   - App wiring: `askNotesOpen` (main pane swap), `askCallOpen` (third flex
     column), shortcuts, source-chip navigation through the existing
     `transcriptFindRequest` timestamp jump; chips for non-session files
     open via `openPath`.
5. **Tests**: Rust - prompt shapes (both scopes, history bounding, language
   rule presence), reply parsing, validation, scope keying, CLI arg
   construction; one `#[ignore]` manual e2e against the real claude CLI.
   React - conversation rendering (question/answer/chips), send flow calling
   `chat_ask`, chip click navigation, sidebar row, search-palette row,
   shortcut gating.
