# Stage 4.4: first public beta readiness

## Objective

Prepare a reviewable beta candidate around the owner's clarified philosophy:
simstim captures calls as durable files; the user's existing AI tools handle
the rest. No proprietary export pipeline, AI credit system or sharing service.

## Global constraints

- Files remain the database. Recording is explicit and audio stays local.
- Existing AI subscriptions work through the user's installed, authenticated
  CLI, subject to that provider's access, usage limits and billing settings.
- In-app questions are read-only; broader actions happen in the user's own
  assistant. Optional connector access must not preapprove an entire server.
- No model downloads in tests, no real calls or private notes in demo assets.
- Preserve the owner's one-screen onboarding and one-page settings decisions.
- All four project gates must pass. The owner tests the candidate before merge.
- Preparing a beta does not make the private repository public or publish a tag.

## Implementation

1. Serialize complete per-file updates and reserve recording paths through
   finalization; add file-content regression tests.
2. Replace wildcard connector approvals with exact read operations and a
   noninteractive deny-by-default permission profile. Test using a synthetic
   connector without personal data.
3. Make privacy copy accurate and the frontend tests reproducible on Node 24.
4. Rewrite README around the workflow; add configuration, privacy, AI usage,
   contribution, support and beta release documentation, plus an MIT license.
5. Prepare an example note and screenshots using synthetic data and the real
   renderer. Keep demonstration helpers out of production builds.
6. Run the four gates, inspect the diff, prepare a local candidate for owner e2e.

## Owner acceptance

On the candidate: open existing notes, record a short two-channel test,
continue it, verify playback and automatic transcription, edit notes while
processing, run a summary and an ordinary question, then a connector lookup.
Check the text-local path with automatic summaries off. Confirm both audio
channels independently. Merge and release follow the owner's result.

## Implementation result (2026-09-09)

All six implementation steps are complete. The four gates pass: 482 Rust
checks (8 ignored) and 223 frontend tests, plus clippy and the production build.
The local app and DMG pass signature-integrity, entitlement and image checks.
The connector smoke test confirms read allowance and write denial even when
project settings preapprove the writer. The release helper preserves numeric
Apple bundle versions for beta tags. See `docs/beta-release.md` for artifacts,
validation details and the still-required owner test before merge/publication.
