# simstim Stage 1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace both stage-1.0 call notifications (the in-app CallBanner and the UN system notification) with one Granola-style floating banner window that looks and works the same on every platform.

**Architecture:** A pre-created hidden Tauri window labelled `banner` renders a small React card (same stack, same dist; `main.tsx` branches on the window label). A pure banner-state controller in src-tauri decides visibility from the detector's `Action`s plus recording start/stop and user dismissal; a thin shell applies decisions (show/hide/position the window, push state as an event). On macOS the window is converted to a non-activating NSPanel (tauri-nspanel) so clicks never steal focus from the call app and the banner shows over full-screen apps. Start/Stop clicks forward as events to the `main` window, which runs the existing `handleStart`/`handleStop`, keeping one code path into recording.

**Tech Stack:** existing workspace + `tauri-nspanel` (git dependency, ahkohd/tauri-nspanel, Tauri v2 branch, pinned to a rev; not on crates.io; used in production by Cap and Screenpipe). No other new deps. `cidre`'s `un` feature is removed with the UN layer.

## Global Constraints

- **Never auto-record** (product principle 5). The banner only forwards a user click into the existing start path.
- **Single affordance.** After this stage there is exactly one call notification surface: the floating banner. No in-app CallBanner, no UNUserNotificationCenter code anywhere in the tree.
- The banner window never takes focus on macOS: non-activating NSPanel, `canJoinAllSpaces | fullScreenAuxiliary | stationary` collection behavior, status-level. Clicking Start while in full-screen Zoom must leave Zoom frontmost. "Open simstim" is the only action that focuses the main window.
- Platform code stays behind the platform boundary: the panel conversion is `#[cfg(target_os = "macos")]`; everything else is plain Tauri API that Windows/Linux will reuse.
- Events and commands (exact names, snake_case payloads like the existing ones):
  - Rust -> banner webview: event `banner-state`, payload `{ kind: "detected", bundle_id, app_name } | { kind: "ended" } | { kind: "hidden" }`.
  - banner webview -> main webview: `emitTo("main", "banner-start", { bundle_id, app_name })` and `emitTo("main", "banner-stop")`.
  - banner webview -> Rust: commands `banner_dismiss()` (X button and auto-dismiss timeout), `banner_current_state()` (called on mount, returns the current payload so a reloaded webview can't miss state), `show_main_window()` (Open simstim: show + focus `main`; the banner stays up, its timer keeps running).
- Auto-dismiss: detected state closes itself after **30 seconds**, with a visible progress strip; hovering the banner pauses the timer (constant in one place with a doc comment). The ended state has no timer: it stays until Stop, dismiss, or the recording stops (auto-stop included; a brief flash of the ended banner before auto-stop lands is accepted).
- Dismiss semantics and the 10-minute per-app cooldown in detect.rs are unchanged; the cooldown is set at fire time, dismissal only hides UI.
- The banner ignores macOS Focus/DND by design and leaves no Notification Center history (spec, deliberate).
- Detected banner is suppressed while a recording is live (detect.rs already suppresses; the controller re-checks as defense).
- Positioning: top-right of the monitor containing the cursor, primary monitor fallback, 16 logical px margins, physical/logical conversion via the monitor's scale factor.
- `signingIdentity: "-"` in tauri.conf.json stays (TCC identity still needs a real bundle signature).
- All existing behavior preserved. Conventional commits, no co-author trailer, no em dashes anywhere. Every task ends with all four gates green: `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `pnpm test`, `pnpm build` (from `apps/desktop`).

### Task B1: banner controller (pure state machine)

**Files:**
- Create: `apps/desktop/src-tauri/src/banner.rs` (module with the pure controller + its tests; the shell comes in B2)
- Modify: `apps/desktop/src-tauri/src/lib.rs` (declare `mod banner;` only)

**Interfaces produced:**
```rust
pub enum BannerState {
    Hidden,
    Detected { bundle_id: String, app_name: String },
    Ended,
}
pub struct BannerController { /* state: BannerState */ }
impl BannerController {
    pub fn new() -> Self;
    // Each returns Some(new_state_to_render) when the visible state changed,
    // None when the input is ignored in the current state.
    pub fn on_detected(&mut self, bundle_id: &str, app_name: &str, recording_live: bool) -> Option<BannerState>;
    pub fn on_detection_cleared(&mut self, bundle_id: &str) -> Option<BannerState>;
    pub fn on_call_ended(&mut self) -> Option<BannerState>;
    pub fn on_recording_started(&mut self) -> Option<BannerState>;
    pub fn on_recording_stopped(&mut self) -> Option<BannerState>;
    pub fn on_dismiss(&mut self) -> Option<BannerState>;
    pub fn current(&self) -> &BannerState;
}
```

Transition table (tests assert exactly this, one test per row group):
- Hidden + on_detected(recording_live=false) -> Detected; recording_live=true -> None (ignored).
- Detected + on_detection_cleared(same bundle_id) -> Hidden; different bundle_id -> None.
- Detected + on_recording_started -> Hidden (the click succeeded, banner leaves).
- Detected + on_detected(other app) -> Detected(other) (latest call wins, matches stage-1.0 in-app behavior where a new payload replaced the old).
- Any state + on_call_ended -> Ended (detect.rs only emits CallEnded for the live recording's app).
- Ended + on_recording_stopped -> Hidden. Ended + on_detected -> None (recording is live by definition of Ended).
- Any visible state + on_dismiss -> Hidden; Hidden + anything that maps to Hidden -> None (no redundant renders).

Tests are plain `#[cfg(test)]` unit tests in banner.rs, no Tauri types in the controller at all. Run: `cargo test -p desktop banner`.

Commit `feat(banner): pure banner window state controller`.

### Task B2: banner window + shell wiring (backend)

**Files:**

**Interfaces produced (shell around the B1 controller):**
```rust
pub struct Banner(/* Mutex<BannerController> + AppHandle */);
impl Banner {
    pub fn create(app: &AppHandle) -> tauri::Result<Banner>; // builds the hidden window, converts to NSPanel on macOS
    pub fn detected(&self, bundle_id: &str, app_name: &str, recording_live: bool);
    pub fn detection_cleared(&self, bundle_id: &str);
    pub fn call_ended(&self);
    pub fn recording_started(&self);
    pub fn recording_stopped(&self);
    pub fn dismiss(&self);
    pub fn current_payload(&self) -> BannerPayload; // for the banner_current_state command
}
```
Each method feeds the controller; on `Some(state)` it emits `banner-state` to the banner window FIRST, then shows (repositioning before show) or hides the window. `Banner` is `app.manage()`d state.

- Window creation in `.setup()` right after `detect::start`: `WebviewWindowBuilder::new(app, "banner", WebviewUrl::App("index.html".into()))` with `.decorations(false).transparent(true).always_on_top(true).skip_taskbar(true).resizable(false).focused(false).visible(false).inner_size(370.0, 120.0).visible_on_all_workspaces(true)`.
- macOS panel conversion behind `#[cfg(target_os = "macos")]`: `tauri_nspanel::init()` plugin + `window.to_panel()`, style mask includes non-activating panel, window level status, collection behavior `canJoinAllSpaces | fullScreenAuxiliary | stationary`. Follow the tauri-nspanel README for the exact API at the pinned rev; if the v2 branch layout differs from this plan, adapt and note it in the commit body.
- Positioning helper (pure function, unit-tested): given monitor position/size (physical px), scale factor, window logical size and a 16 px logical margin, return the physical `(x, y)` for top-right. Shell picks the monitor via cursor position (`app.cursor_position()` + `monitor_from_point`), falling back to `primary_monitor()`.
- `emit_actions` in detect.rs: `Action::Detected` also calls `banner.detected(..)` (the recording_live flag comes from the same suppression state detect already tracks), `Action::DetectionCleared` -> `banner.detection_cleared(..)`, `Action::CallEnded` -> `banner.call_ended()`. The existing `call-detected`/`call-detection-cleared`/`call-ended` app-wide events KEEP being emitted (main window still consumes `call-ended` for auto-stop, and B4 rewires the rest).
- lib.rs: the command that starts a recording calls `banner.recording_started()` on success; the stop command calls `banner.recording_stopped()` (find them where `detect` state gets `mark_recording_started`/`recording_stopped`, lib.rs around lines 271 and 317, and mirror those call sites).
- New commands registered: `banner_dismiss`, `banner_current_state`, `show_main_window`.
- The UN `system_notification::post` call in `emit_actions` and the `!tauri::is_dev()` guard stay untouched in this task (removal is B5, keeps this diff reviewable).

Tests: positioning helper unit tests (both 1.0 and 2.0 scale factors, monitor not at origin); controller wiring is covered by B1; window behavior is manual. Manual verification step (implementer runs, macOS): `pnpm tauri dev`, temporarily call `banner.detected("test", "Test", false)` from setup (remove before commit) or trigger a real detection; confirm the window appears top-right, over a full-screen app, and clicking inside does not deactivate the frontmost app.

### Task B3: banner webview UI

**Files:**
- Create: `apps/desktop/src/banner/BannerApp.tsx`, `apps/desktop/src/banner/BannerApp.test.tsx`
- Modify: `apps/desktop/src/main.tsx` (branch on window label), `apps/desktop/src/index.css` only if a transparent-body class is needed

**Interfaces consumed:** `banner-state` event + `banner_current_state`, `banner_dismiss`, `show_main_window` commands from B2.
**Interfaces produced:** `emitTo("main", "banner-start", { bundle_id, app_name })`, `emitTo("main", "banner-stop")` (B4 consumes).

- `main.tsx`: `getCurrentWebviewWindow().label === "banner"` renders `<BannerApp />` (no StrictMode double-effects surprises with the timer: keep StrictMode, make effects idempotent), anything else renders `<App />` as today.
- `BannerApp`: transparent page, one rounded card (theme tokens, CSS shadow, since the window is transparent and shadowless). Applies theme the same way App does (`getConfig().then(initTheme)`).
  - detected: title "Call detected", subtitle app_name, primary button "Start recording", ghost link "Open simstim", X. Progress strip along an edge draining over 30 s (`AUTO_DISMISS_MS = 30_000`); `onMouseEnter` pauses, `onMouseLeave` resumes; at zero it invokes `banner_dismiss`.
  - ended: title "Call seems over", primary button "Stop", X. No strip.
  - hidden: renders nothing (Rust hides the window; the empty render is belt and braces).
- Buttons: Start -> `emitTo("main", "banner-start", payload)`; Stop -> `emitTo("main", "banner-stop")`; X -> `invoke("banner_dismiss")`; Open simstim -> `invoke("show_main_window")`.
- On mount: `invoke("banner_current_state")` seeds state, then subscribe to `banner-state`.

Tests (vitest, same patterns as App.test.tsx, mock `@tauri-apps/api`): renders detected state with app name; Start emits `banner-start` to `main` with the payload; Stop emits `banner-stop`; X invokes `banner_dismiss`; fake timers: strip reaches zero -> `banner_dismiss` invoked once; hover pauses (advance timers while hovered, no dismiss).

Commit `feat(ui): floating banner webview with auto-dismiss progress`.
