# simstim Stage 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Detect that a call started (an app from a whitelist grabbed the microphone) and offer one-click recording; suggest stopping when the call ends. Never record automatically.

**Architecture:** A new `detect` module in src-tauri built on Core Audio process objects via cidre (see `docs/research/detection.md`: APIs verified, no permissions needed): a system-level listener on the default input device's "running somewhere" flag triggers a process scan, identity resolution and whitelist matching behind a debounce and per-app cooldown. Detection emits Tauri events; the frontend renders a banner whose click calls the existing `start_recording`. Call-end mirrors it with a stop suggestion and an optional auto-stop.

**Tech Stack:** existing workspace. cidre (already full-featured in our build), `objc2-app-kit` ONLY if cidre's ns bindings do not already cover NSRunningApplication (check first; prefer zero new deps).

## Global Constraints

- **Never auto-record.** Detection may only emit events and render suggestions; the sole path into `start_recording` is a user click. This is product principle 5 and non-negotiable.
- Detection requires no TCC permission (verified in research); if any code path ends up prompting for something, that is a bug in the approach: stop and reconsider.
- Event-driven, not polling: listener on `HW_DEFAULT_INPUT_DEVICE` (system object) + `DEVICE_IS_RUNNING_SOMEWHERE` (current default input device), re-subscribing when the default device changes. A process scan runs only when the device flag flips (plus a short settle re-scan; the research documents a race with short-lived processes).
- Identity resolution chain (research-verified, in order): Core Audio bundle_id as a fast hint -> NSRunningApplication by pid -> walk to the OUTERMOST .app bundle on the path (maps Chrome/Brave helpers to the browser) -> executable path -> raw pid. FaceTime/iPhone-Continuity both capture under `com.apple.avconferenced`/TelephonyUtilities: label by the active front app when that bundle is seen.
- Whitelist (bundle id -> display name), a static table with these verified ids: `us.zoom.xos` Zoom, `com.tinyspeck.slackmacgap` Slack, `com.microsoft.teams2` Teams, `com.cisco.webex` Webex, `com.apple.FaceTime` FaceTime (via the avconferenced rule), `com.hnc.Discord` Discord, `ru.keepcoder.Telegram` Telegram, `net.whatsapp.WhatsApp` WhatsApp, `com.google.Chrome` Chrome, `com.brave.Browser` Brave, `com.apple.Safari` Safari, `company.thebrowser.Browser` Arc, `app.zen-browser.zen` Zen. Browsers are labelled by browser name only.
- Debounce: a whitelisted app must hold the mic for **5 continuous seconds** before we surface anything (a Slack notification ping is not a call). Per-app cooldown: **10 minutes** after a banner fires (dismissed or acted on), so rejoining the same call does not spam. Both constants in one place with doc comments.
- Our OWN recording must never trigger detection (we open the mic too): exclude our own pid and, while a recording is live, suppress new-call banners entirely (a second simultaneous call suggestion has no sane recording answer in a single-session app).
- IPC/events:
  - Event `call-detected` payload `{ bundle_id: String, app_name: String }`.
  - Event `call-ended` payload `{ bundle_id: String }` (fires when the app that triggered the CURRENT detection-started recording releases the mic; not a general firehose).
  - `set_detect_calls(bool)`; config `detect_calls: bool`, serde default **true** (it only ever suggests). `auto_stop_after_call: bool`, serde default **false**.
- Frontend: a slim banner (not a dialog) above the header or below it, theme-correct, keyboard-accessible: "Call detected: Slack" + [Start recording] + dismiss (X). Clicking start behaves exactly like the header Record button except the new note's title is prefilled with the app name and time (e.g. "Slack call 14:30"). Banner auto-dismisses if the app releases the mic before the user reacts. Call-end: if the recording was started FROM a detection banner and `call-ended` fires, show "Call seems over" with [Stop] (or stop automatically when `auto_stop_after_call` is on, going through the exact same stop path as the button).
- System notification via `cidre::un` (UNUserNotificationCenter): best-effort layer, attempted only when not in dev (`tauri::is_dev()` false) and failures are silently logged, never surfaced as errors. Its click focuses the app (default action); the banner remains the real affordance. QA note in the plan: this part can only be manually verified against a real `tauri build`.
- All existing behavior preserved. No telemetry. Conventional commits, no co-author, no em dashes. Every task ends with `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `pnpm test`, `pnpm build` green.

### Task D1: detect module (backend)

**Files:** new `apps/desktop/src-tauri/src/detect.rs` (+ submodules if it grows), `lib.rs` (state + event wiring + config commands), `config.rs` (two new fields), `src/lib/ipc.ts` (types only).

**Interfaces produced:**
- `detect::start(app_handle, initial_enabled) -> DetectHandle` (spawns the listener machinery; `DetectHandle` supports enable/disable without tearing down, and clean shutdown on drop).
- Emits `call-detected` / `call-ended` per Global Constraints; honors debounce, cooldown, own-pid exclusion, recording-suppression (reads the existing AppState).
- The state machine (mic-active spans per bundle id -> debounce -> fire -> cooldown; call-end tracking for the active detection) is a PURE struct with injected clock, fully unit-tested without Core Audio: blip shorter than debounce never fires; fire -> cooldown suppresses; end event only for the bundle that started the current recording; device-change resubscription logic testable via a trait seam if cheap, otherwise documented as manually verified.
- Identity resolution as its own function with the research's fallback chain; unit-test the outermost-bundle path walk with synthetic paths (the NSRunningApplication call itself is a thin seam).

Manual verification step (implementer runs): a probe bin or ignored test that prints detection events live; start a mic-using process (e.g. ffmpeg avfoundation or QuickTime record) NOT on the whitelist (no event) and simulate a whitelisted one by temporarily adding the terminal/ffmpeg bundle to a test whitelist (event fires after debounce). Report the real output.

Commit `feat(detect): core audio call detection with whitelist and debounce`.

## Self-review notes

- The pure state machine is the heart: everything Core Audio is a thin shell around it, so the debounce/cooldown/suppression logic gets real tests without hardware.
- The research explicitly warns the naive per-process-listener design loses a race; the plan mandates the device-level pattern. A reviewer should treat per-process listeners as a red flag.
- The notification layer is deliberately last and deliberately optional: the banner is the product; UN notifications are polish that only fully works signed.
- start_recording with a prefilled title touches the continuation path (title must only apply to NEW notes, never overwrite an existing note's title): D2 must guard and test that.
