# simstim Stage 0.6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the app into an Anarlog-style notes shell: sidebar of sessions read from the output folder, session view with editable title + user notes + transcript, interim (draft) transcript lines while speaking, light/dark themes following the system.

**Architecture:** File format v2 (title/duration frontmatter, Notes section, parser) in the transcript crate; session IPC layer (list/read/save) with a strict single-writer rule (recording worker owns the active file, UI edits route through it); interim decoding inside the session worker with skip-if-busy throttling; frontend restructured into Sidebar + SessionView + header recording controls; theme tokens restored to light-default + .dark with a config-driven 3-way override.

**Tech Stack:** existing workspace; no new heavyweight deps (frontmatter parsing by hand or `serde_yaml` for the frontmatter block only).

## Global Constraints

- The .md files in the output folder remain the ONLY store. No index files, no caches, no DB. `list_sessions` scans the folder on each call (a call transcript folder has tens to hundreds of files; a frontmatter-only read per file is fine).
- File format v2 (the transcript crate renders AND parses it; round-trip lossless for title/notes/transcript):

```markdown
---
date: 2026-08-15T12:30:00+02:00
title: Weekly sync
asr: parakeet-tdt-0.6b-v3
duration: 32m        <- written on stop; absent while recording
---

## Notes

<user notes, verbatim markdown, may be empty>

## Transcript

[00:00:12] Me: ...
```

- Filenames: `YYYY-MM-DD HH-mm-ss call.md` (seconds added: fixes same-minute collision). Existing v1 files (no title, no Notes section, old filename) must still parse (title falls back to "Untitled", notes empty). Title edits never rename files.
- Single-writer rule: while a recording session is active, ONLY its worker writes that file. UI edits to the active session go through `update_active_session`. `save_session` must reject the active session's path with a clear error. Inactive-session saves: parse -> modify -> atomic tmp+rename (existing pattern).
- Tauri IPC contract (exact names; extend src/lib/ipc.ts, single typed source):
  - `list_sessions() -> Vec<SessionMeta { path: String, title: String, date: String /*RFC3339*/, duration_secs: Option<u64> }>` sorted by date desc; skips files that fail to parse (they are not ours).
  - `read_session(path: String) -> SessionData { title: String, date: String, notes: String, transcript: String /* raw section text */ }`
  - `save_session(path: String, title: String, notes: String) -> Result<(), String>` (inactive sessions only)
  - `update_active_session(title: Option<String>, notes: Option<String>) -> Result<(), String>` (recording only)
  - `get_config`/`set_output_dir`/`set_active_model`/`list_models`/`download_model`/`start_recording`/`stop_recording` unchanged; `set_theme(theme: String)` added; config gains `theme: "system" | "light" | "dark"` (default "system").
  - Events: `transcript-line` (unchanged, final lines); NEW `transcript-interim` payload `{ channel: "me" | "them", text: String }` (empty text clears that channel's draft); NEW `session-error` payload `{ message: String }` (worker-side errors surfaced instead of eprintln-only).
- Interim decoding: only while VAD reports active speech on a channel; decode the accumulating (not yet finalized) buffer for that channel; throttle: never start a new interim decode while one is running (skip-if-busy), minimum 400ms between interim decodes per channel, buffer must have grown since last decode. Interim lines are NEVER written to disk.
- Investigate max_speech_duration: brief the implementer to determine empirically why an 8s cap did not split a 15s monologue (sherpa vad semantics), fix or adjust config so continuous speech finalizes in <=10s chunks, and cover with a test using a long synthetic speech-like signal or concatenated test wavs.
- Themes: shadcn tokens: `:root` = light values, `.dark` block = dark values (this restores the stock shadcn arrangement; the 0.5 dark-as-root hack is reverted). The `dark` class on `<html>` is managed at runtime: config theme "system" follows `window.matchMedia("(prefers-color-scheme: dark)")` (with change listener), "light"/"dark" force. No FOUC: apply before first paint (inline module in index.html or synchronous init before React mounts using the persisted config via localStorage mirror is NOT allowed (config.json is the source): acceptable startup: default to system-dark-match immediately, then reconcile after get_config resolves).
- First commit of the stage (from the 0.5 final review): a test asserting `config::KNOWN_MODEL_ID` resolves in `models::REGISTRY` and the registry's dir_name matches the engine's hardcoded model dir.
- No telemetry. Conventional commits, no AI co-author lines. No em dashes in authored copy. All suites stay green, clippy -D warnings clean.

### Task 1: Registry consistency test + file format v2 + parser (transcript crate)

**Files:** `crates/transcript/src/lib.rs` (+tests), `apps/desktop/src-tauri/src/models.rs` (consistency test only)

**Interfaces produced:**
- `Transcript` gains `title: String` (default "Untitled"), `notes: String`, `set_title/set_notes`, `set_duration_secs(u64)`; `render()` emits format v2 exactly as in Global Constraints (duration line only when set).
- `pub struct SessionData { pub title: String, pub date: String, pub notes: String, pub transcript: String }`
- `pub fn parse_session(path: &Path) -> anyhow::Result<SessionData>` (v2 and v1 files; unknown files -> Err)
- `pub fn parse_meta(path: &Path) -> anyhow::Result<SessionMetaRaw { title, date, duration_secs }>` (frontmatter-only fast path for listing; reads at most the frontmatter block)
- `output_path` filename gains seconds: `%Y-%m-%d %H-%M-%S call.md`
- Round-trip property test: render -> parse_session -> fields equal (incl. multiline notes with markdown headers inside NOT confused with section markers: notes containing a literal line `## Transcript` is the known edge: document the chosen escape/limitation in a test).
- models.rs: consistency test per Global Constraints.

TDD throughout; commit `feat(transcript): file format v2 with title, notes and parser`.

### Task 2: Session IPC + single-writer routing

**Files:** `apps/desktop/src-tauri/src/lib.rs`, `src/session.rs`, new `src/sessions.rs` (list/read/save commands), `src/config.rs` (theme field), `src/lib/ipc.ts` (types only, no UI)

**Interfaces produced:** the IPC contract from Global Constraints (list_sessions/read_session/save_session/update_active_session/set_theme). Session worker: `Transcript` now carries title/notes; `update_active_session` sends into the worker via a command channel (extend the worker's message enum or a shared Mutex the worker reads before each save: pick one, document it); every worker save persists current title/notes; on stop, duration written. `session-error` event replaces silent eprintln in the worker's error paths (keep eprintln too). `start_recording` unchanged externally (still returns path).

Tests: sessions list/read/save on tempdir fixtures (v1 + v2 files + junk .md skipped); save_session rejects active path (unit-testable by injecting active-path state); config theme default "system".

Commit `feat(sessions): folder-backed session ipc with single-writer routing`.

### Task 3: Interim decoding + max_speech investigation

**Files:** `apps/desktop/src-tauri/src/session.rs`, `crates/engine/src/lib.rs` (only if the Vad API needs to expose the current in-progress buffer; prefer keeping raw per-channel accumulation in session.rs: the session already receives chunks, it can keep its own rolling current-utterance buffer gated by a new lightweight `Vad::is_speech_active()` if the sherpa API exposes it, else track "speech active" as "samples since last finalized segment > min_speech").

**Behavior:** per Global Constraints (skip-if-busy, 400ms min cadence, only while speech active, emit transcript-interim, clear on finalize with empty-text event). Max_speech investigation: reproduce with a synthetic or looped speech wav in a test; report findings in the task report; land either a sherpa config fix or a session-level forced cut at 10s of continuous speech (whichever is correct), covered by a test asserting no finalized segment exceeds ~10s worth of samples.

**Perf guard:** measure interim decode time for a full 8s buffer on this machine (report the number); if a single interim decode of the max buffer exceeds ~1.5s, decode only the most recent 8s of the buffer.

Commit `feat(session): interim transcript decoding while speaking`.

### Task 6: Session view: title, notes editor, transcript with interim
